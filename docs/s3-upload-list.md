# S3 upload list — ECS preservation data

What needs to be in the public bucket for the crop links on
<https://avweigel.github.io/ecs-analysis/crops.html> to work without the Janelia VPN.

Generated by `python scripts/build_neuroglancer.py --probe`, which checks the bucket
object by object. Re-run it after each upload batch and the site updates itself.

## Destination layout

Identical to NRS below the root, so this is a copy with the origin swapped:

```
NRS   /nrs/cellmap/data/<dataset>/<dataset>.zarr/recon-1/...
S3    s3://<bucket>/<dataset>/<dataset>.zarr/recon-1/...
```

Two things per dataset:

```
  recon-1/em/<array>/                     the image volume  (large)
  recon-1/labels/groundtruth/<crop>/      one group per crop (small)
```

Each crop group on NRS holds ~55 label arrays (every organelle class).
**This work needs only four of them:** `all`, `cell`, `ecs`, `bm`.
Uploading the whole group is fine if that is simpler — the site only reads `all`.

## Keeping it out of the OpenOrganelle portal

`janelia-cosem-datasets` is the bucket the OpenOrganelle portal itself serves from.
I could not establish from outside whether putting objects there is enough to make a
dataset appear on the site, or whether the portal reads a separate registry — the
portal is a single-page app and its repository does not document the discovery step.

If the data must stay unlisted, the reliable answer is to use a different bucket rather
than to rely on not being indexed. The site needs a one-line change to follow:
`PUBLIC_S3_BASE` in `scripts/build_neuroglancer.py`. Whatever bucket is used needs
public read and CORS enabled, since Neuroglancer fetches directly from the browser.

Worth confirming with whoever maintains the portal before uploading, since moving data
afterwards is more work than choosing the bucket now.
